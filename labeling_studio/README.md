# YOLO Dataset Studio — 데이터 세척 · 라벨링

> `sasac8_ilbin` 안의 **독립 하위 프로젝트**다. 이 폴더 밖은 건드리지 않는다.
> `.gitignore` 와 `.gitattributes` 를 루트가 아니라 여기 두는 이유가 그것이다 —
> 이 도구는 `models/` 를 학습 결과(가중치) 폴더로 쓰는데 루트의 `models/` 는
> 팀의 파이썬 패키지다. 규칙을 루트에 두면 팀 소스가 git 에서 사라진다.
> 가상환경도 `labeling_studio/.venv` 안에 따로 들어간다.

라벨 없는 이미지에서 YOLO 라벨을 재구성하는 파이프라인. 사람이 라벨링하는 동안
GPU 가 뒤에서 학습하고, 새 모델이 나오면 아직 안 연 이미지에 예측을 깔아준다.
사람은 학습을 기다리지 않는다.

**목표는 좋은 검출기가 아니라 이식 가능한 절차다.** 성공 기준도 mAP 가 아니라
**사람 편집 비용**이다 — 누락=그리기 5초, 오검출=삭제 1초, IoU 0.5~0.75=조정 3초,
0.75 이상=무료.

## 폴더 구조

```
<루트>/
├── db/<데이터셋>/       원본 이미지 + 라벨. 읽기 전용으로 봉인한다.
├── work/<작업공간>/     라벨만 보관 (이미지 없음)
│   ├── workspace.json      소스 참조 · 설정 · 계보 · 연속형 설정
│   ├── labels/<split>/     편집 결과 (순수 YOLO = 그대로 학습 가능)
│   ├── meta/<split>/       출처 태그 · 신뢰도 · 편집량 · 실측 소요시간
│   └── jobs/               학습 작업 큐 (queued / running / done)
├── models/<모델>/       가중치 · model.json(내력) · preds/
└── export/<이름>/       내보낸 학습용 데이터셋 (이미지 실제 복사)
```

**`db/` 를 건드리는 쓰기 코드는 이 저장소 어디에도 없다.** 작업공간이 없으면
편집 자체가 잠긴다. `db/` `work/` `models/` `export/` 는 전부 `.gitignore` 에 있다 —
코드만 버전 관리하고 데이터는 각자 로컬에 둔다.

## 설치 · 실행

**`스튜디오 실행.bat` 을 누르면 끝난다.** `.venv` 가 없으면 런처가 알아서 만들고
의존성까지 깐다(첫 실행만, 몇 분). 필요한 건 **파이썬 3.9 이상**뿐이다 —
설치할 때 `Add python.exe to PATH` 를 켜 두어야 한다.

| 파일 | 하는 일 |
|---|---|
| `스튜디오 실행.bat` | 준비 + 실행 (평소 이것만 쓴다) |
| `스튜디오 실행 (콘솔).bat` | 같지만 콘솔을 띄워 로그를 본다 |
| `설치.bat` | 준비만 하고 끝낸다 |
| `학습 워커 실행.bat` | 스튜디오 없이 학습 큐만 비운다 (밤새 돌리기 등) |

```powershell
# 직접 부르고 싶으면
.\launch.ps1              # 준비 + 실행
.\launch.ps1 -SetupOnly   # 준비만
.\launch.ps1 -Setup       # venv 가 있어도 다시 설치
.\launch.ps1 -Worker      # 학습 워커
```

### torch 는 런처가 GPU 를 보고 고른다

이게 이 프로젝트에서 제일 잘 깨지는 부분이라 자동으로 처리한다.
`pip install ultralytics` 는 torch 를 의존성으로 끌고 오는데, 아무 휠이나 깔리면
GPU 세대에 따라 CUDA 가 안 잡힌다. 그래서 **torch 를 먼저** 맞는 인덱스에서 깔고
나머지를 깐다. `requirements.txt` 에 torch 가 없는 이유도 이것이다.

| 감지된 GPU | 고르는 인덱스 |
|---|---|
| RTX 50xx (Blackwell · sm_120) | `nightly/cu130` — 안정판으로는 실행되지 않는다 |
| 그 외 NVIDIA | `cu124` 안정판 |
| 없음 | CPU 휠 |

런처는 `YOLO_AUTOINSTALL=false` 도 설정한다. ultralytics 가 의존성이 빠졌다고
판단하면 **시스템 파이썬에** 자동 설치를 시도하는데, 실제로 CLIP 을 깔려다
torch 를 재설치하려 한 적이 있다. 성공했다면 CUDA 가 깨졌을 것이다.

## 쓰는 법

```
1. "스튜디오 실행.bat"
2. 시작 메뉴에서 ① 연속 라벨링
3. 라벨링한다. 끝.
```

학습 워커는 스튜디오가 자동으로 띄우고, 닫을 때 곱게 거둔다(현재 학습을 마치고
스스로 나간다 — 강제 종료하면 몇 분짜리 학습이 통째로 날아간다).

| 키 | 기능 |
|---|---|
| `w` / `s` | 이전 / 다음 이미지 (넘어갈 때 자동 저장) |
| `Tab` | 라벨·예측을 통째로 감췄다 되돌리기 (원본 확인) |
| `~` | 지우개 — 드래그로 감싼 라벨을 지운다 |
| `1`~`9`, `0` | 그릴 클래스 |
| `Delete` | 선택 박스 삭제 |
| `Ctrl+A` | 이 이미지의 라벨을 전부 지우기 |
| `Ctrl+Shift+A` | 남은 예측을 전부 라벨로 승격 |
| `Ctrl+Z` / `Ctrl+S` | 되돌리기 / 저장 |

## 설계에서 물러설 수 없는 것

- **워커는 별도 프로세스여야 한다.** 스레드로 돌리면 ultralytics 가 GIL 을 잡고
  있는 동안 Tkinter UI 가 얼어붙는다.
- **통신은 소켓이 아니라 파일로.** `work/<작업공간>/jobs/{queued,running,done}` 에
  요청을 떨어뜨리고 `os.rename` 으로 집어간다. 원자성은 파일시스템이 보장하므로
  워커가 둘이어도 중복 실행이 없고, 워커가 죽어도 요청이 폴더에 남는다.
- **밀린 요청은 가장 최근 것만 실행한다.** 오래된 것부터 처리하면 이미 낡은
  라벨로 학습하게 된다.
- **검수 안 한 이미지는 학습에 안 들어간다.** `meta` 기록이 있는 것만 쓴다.
  빈 라벨 파일은 "봤는데 없었다"는 유효한 판정이다.
- **새 데이터셋의 0번 작업은 `dedup_dataset.py`.** 웹에서 모은 데이터셋은 스플릿 간
  중복을 거의 항상 갖고 있고, 재인코딩되어 있어 **파일 해시로는 안 잡힌다.**

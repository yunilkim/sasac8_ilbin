# 라벨링 규약 — vest-helmet

이 문서는 **판정 기록**이다. 판정은 전부 사람(사장님)이 하고, 여기에는 받아적기만 한다.
애매한 케이스가 나올 때마다 아래 판정 목록에 추가한다.

작성 시작 2026-08-16 · 대상 데이터셋 `db/vest-helmet` · 클래스 `0 reflective_jacket` / `1 safety_helmet`

---

## 0. 출처 태그 — 권위 순서대로 내려간다

| 태그 | 뜻 | 비고 |
|---|---|---|
| **A** | 사람 | 사람이 직접 그리거나 고친 것. 가장 높다 |
| **B** | GT | 데이터셋 원본 주석자. 익명 · 규약 문서 없음 · `db/` 에 봉인 |
| **C** | 학습된 모델 | |
| **D** | zero-shot | 이 데이터셋을 한 번도 안 본 공개 가중치 |

**A > B > C > D.** 앞선 글자가 이긴다.
사람이 아직 보지 않은 이미지에서는 B 가 유일한 기준으로 남는다.

B 를 부정하는 것이 아니라 제자리에 놓는 것이다 — B 는 문서화된 벤치마크가 아니라
Roboflow Universe 에 개인이 올린 결과물이고, README 에 주석 기준이 한 줄도 없다.

**출처와 검증은 다른 축이다.** 모델이 그린 박스(C)를 사람이 보고 승인해도 출처는 C 로 남는다.
승격시키면 검수를 마친 이미지가 전부 A 가 되어 자동화율이 0 으로 수렴한다.
검증 여부는 박스가 아니라 **이미지 단위**로 기록된다(작업공간에 meta 기록이 있으면 검증된 것).

최종 보고는 **A+B(사람이 만든 라벨) 대 C+D(기계가 만든 라벨)** 로 낸다.

> 2026-08-16 개정. 이전에는 A=GT복사(시뮬레이션) / B=사람편집 이었다.
> 권위 순서와 글자 순서가 어긋나 직관에 반했으므로 A 와 B 를 맞바꿨다.
> 개정 시점에 저장된 라벨이 0장이라 마이그레이션은 없었다.

## 1. 확정된 규칙

### R1. 실제 객체여야 한다 — 닮은 것은 제외
빛 반사, 블러, 색 얼룩 등으로 **그렇게 보이는 것**은 라벨하지 않는다.

> 판정 근거: `00017` — 램프 불빛에 머리카락이 빛나는 것을 헬멧으로 잘못 본 사례.
> 블러 때문에 헷갈린 것으로 보임.

### R2. `reflective_jacket` 은 반사재가 기준이다 — 색이 아니다
노란색·형광색 옷이라도 **반사 스트립이 없으면 제외**한다.
클래스 이름이 `reflective_jacket` 이므로 소매 유무(재킷/조끼)는 기준이 아니다.

> 판정 근거: `04875` — "그냥 노란 옷임".

### R3. 박스는 가려진 부분까지 덮는다 (amodal)
객체의 일부가 가려져 있어도 박스는 **객체의 전체 범위**를 덮는다.
가시 영역만 감싸지 않는다.

> 판정 근거: `07808` — "가려진 부분까지 박스가 쳐져야 하는데
> 지금 상태는 이미지 끝에 걸쳐져 있어서 가려진 부분 전체에 박스가 쳐 있지도 않음".

**형식상 제약:** YOLO 좌표는 0~1 이라 이미지 밖으로 나가는 박스를 표현할 수 없다.
객체가 이미지 경계에서 잘린 경우 박스도 경계에서 잘린다. R3 은 이미지 안에서만 적용된다.

### R4. 맥락으로 판단할 수 있을 때만 라벨한다
형태가 가려져 있어도 **주변 맥락**(사람 머리·몸, 착용 상태 등)이 그것을 뒷받침하면 라벨한다.
맥락 없이 **"그것처럼 보이는 느낌"만으로는 라벨하지 않는다.**

> 판정 근거: `07808` — "맥락으로 헬멧이라 판단되면 라벨한다. 지금 저 상태는
> 머리라고 보이는 것도 없고 그냥 헬멧 같은 느낌이 있는 것뿐."

**R3 과 R4 의 관계:** R4 가 먼저다. R4 로 "라벨한다"가 정해진 뒤에 R3 이 "어디까지 덮을지"를
정한다. 판단 근거가 없으면 박스를 어떻게 그릴지 물을 필요도 없다.

크기 기준(짧은 변 N px 미만 제외)은 두지 않는다 — 작아도 맥락이 있으면 라벨하고,
커도 맥락이 없으면 라벨하지 않는다.

### R5. 한 객체 = 한 박스 — 쪼개지도, 묶지도 않는다
R3(amodal)의 따름정리다. 박스의 개수는 **객체의 개수**를 따른다.

- **쪼개지 않는다.** 자세·팔·가림 때문에 조끼가 좌우로 갈라져 보여도 하나의 조끼는
  박스 하나다. 보이는 조각마다 박스를 치지 않는다.
- **묶지 않는다.** 나란히 붙어 있는 헬멧 두 개를 한 박스로 감싸지 않는다.

> 판정 근거: `05524` — 헬멧 두 개(`#5` 왼쪽, `#2` 오른쪽)를 각각 잡아 두고
> 그 둘을 통째로 감싸는 `#6` 이 하나 더 있었다. `#6` 삭제.

**모델 예측에서 특히 흔하다.** 135장 실측에서 사람과 모델이 이렇게 갈렸다:

| | 장당 조끼 | 내포(포함율 0.8↑) | 큰겹침 |
|---|---|---|---|
| GT | 1.89개 | 3 | 0 |
| 사람(사장님) | 1.92개 | 3 | 1 |
| **모델 v4 예측** | **3.29개** | **27** | **6** |

**원인은 NMS 의 구조적 한계다.** NMS 는 IoU 로 중복을 지우는데, 작은 박스가 큰 박스
안에 완전히 들어가면 IoU 가 낮다(면적 100 이 면적 1000 안에 있으면 IoU 0.1). 임계값
0.7 에 한참 못 미치므로 **내포 중복은 NMS 를 통과한다.** 모델이 세져도 저절로 사라지지
않는 형태이고, 사람이 지운 결과가 다음 학습에 들어가야 줄어든다.

**단, 포함 관계가 항상 오류인 것은 아니다.** 앞뒤로 겹쳐 쌓인 물체(진열된 헬멧 더미)는
R3 을 지키면 박스가 정상적으로 겹친다. 자동 검사는 **점검 대상을 고르는 용도**이지
판정이 아니다.

> 반례: `00305` — 헬멧 진열 사진. `#0` 과 `#4` 가 77% 겹치지만 앞뒤로 쌓인 서로 다른
> 헬멧이므로 R5 위반이 아니다. 이 사진의 쟁점은 Q2 다.

## 2. 아직 정하지 않은 것

판정이 필요할 때 여기에 답을 채운다.

### Q2. 제품 사진·일러스트도 라벨하는가?
데이터셋에 흰 배경의 조끼 카탈로그 사진과 헬멧 일러스트가 섞여 있다.

> 걸린 사례: `00305` — 흰 헬멧을 앞뒤로 쌓아 놓은 진열 사진.
> GT 는 3개, 사람은 6개를 잡았다. **쌓인 것을 몇 개까지 세는가**가 함께 걸린다.
> (겹침 자체는 R3 상 정상이다. 문제는 세는 범위다.)

### Q3. 사람이 착용하지 않은 물건도 라벨하는가?
손에 들고 있거나 바닥에 놓인 헬멧.

> 걸린 사례: `06540` — 바닥에 쌓인 헬멧 더미 + 뒤쪽 군중.

## 4. 이 문서를 쓰는 이유

한 사람이 170장을 여러 시간에 걸쳐 라벨하면 **첫 30장과 마지막 30장의 기준이 달라진다.**
그때그때 정하고 넘어가면 같은 상황에서 다르게 판정하게 되고, 그러면 편집 비용 측정에
"자동화가 부족해서"인지 "내 기준이 흔들려서"인지 구분할 수 없는 잡음이 섞인다.

그리고 이 프로젝트의 최종 목적은 총기·과일 같은 **새 도메인으로 옮길 수 있는 절차**를
확정하는 것이다. 새 도메인에는 GT 가 아예 없다. **규약을 정하고 문서로 남기는 것 자체가
그 절차의 일부**다 — vest-helmet 에서 연습하지 않으면 새 도메인에서 똑같이 막힌다.
